# Чтение звуков и +Drive: исследование 3 октября 2026

Целевой прибор: Digitone II OS 1.10D build 0049. Ниже результаты чтения опубликованных документов, а не новые аппаратные проверки приложения. Исходники внешних реализаций не переносились.

## Что означает пресет

Официальное руководство OS 1.10C §9.1 описывает 2048 пресетов +Drive (8 банков по 256) и отдельный pool из 128 пресетов в проекте. Звук, загруженный в паттерн, становится независимой копией. §13.5 описывает приём пресетов в выбранный слот +Drive, но не внутренние адреса запросов. Следовательно, утверждение upstream pattern doc «DN2 has no sound pool» ошибочно; отсутствие sound messages в одном пустом дампе не доказывает отсутствие pool. [Руководство Elektron](https://www.elektron.se/wp-content/uploads/2025/07/Digitone-2-User-Manual_ENG_OS1.10C_250708.pdf).

## Доступные данные паттерна

Публикация для 0049 описывает kit с позиции 89088, длиной 10752: magic `BEEFBACE`, версия 3. Внутри kit:

| Блок | Начало | Размер | Метаданные |
|---|---:|---:|---|
| Synth, трек 0–15 | `60 + track × 359` | 359 | magic +0, версия 2 +4, tagMask +8, имя +12 (16 байт) |
| MIDI, трек 0–15 | `5964 + track × 268` | 268 | magic +0, версия 2 +4, имя +8 |

Автор отмечает, что MIDI mask ещё не определён. Вывод имени synth-структуры не подтверждает тип трека или полноту параметрического редактора. [Исследование структуры](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/dn2-pattern-format.md).

Общая документация dump называет `0x63 → 0x53` чтением sound-pool slot, `0x62 → 0x52` чтением kit. Это не адрес текущего несохранённого звука; аппаратная проверка этих операций нашим приложением отсутствует. [Описание SysEx](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/elektron-sysex-protocol.md).

## +Drive: отдельное API

В API-заголовке `F0 00 20 3C 10 00` opcode `0x53` означает List, а не sound dump. Опубликованные проверки List/Read/Write относятся к **1.10E build 0050**; для 0049 известен список поддерживаемых opcode, совместимость ещё не проверена.

List args: `path:str0`, `start:u32be`, `count:u32be`; 0/0 запрашивает всё. Reply `0xD3`: status, echoed start, next cursor, entry count (три u32). Префикс записей описан недостаточно для надёжного полного декодера. Пути включают `/soundbanks/H`, `/kits/A`, `/projects`.

Read операции: Open `54`, Read `55`, Close `56`. Write: `57`, `58`, commit `59`; Move `5A`, Copy `5B`, Delete `5C`. Для Open/Read нет полной схемы аргументов в этом документе. Успешен только один chunk записи; продолжение нескольких chunks завершалось ошибкой checksum. Эти операции пока не включать в transport приложения. [Документ +Drive](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/plus-drive-file-api.md).

## Следующий шаг приложения

Сохранять локальный архив выбранного трека из уже прочитанного паттерна: оба неизменённых блока synth/MIDI, исходный `.syx`, слот и трек, источник, дата, OS/build. Показывать известное имя и сырой tagMask; не угадывать machine, MIDI mask или смысл остальных полей. Проверять рамку, checksum, длину и версии при импорте. Это полезная основа библиотеки до подтверждения полноценного восстановления.

Адрес чтения текущего edit buffer не установлен. Следующая аппаратная фикстура: baseline → один параметр SYN → повторный read → сравнение с дисплеем; отдельно PERFORM KIT mode. Не называть dump выбранного слота «текущим звуком» до проверки, что он отражает несохранённые изменения.

Дополнительная первичная публикация [DNX](https://github.com/NoiseAndMatter/DNX) сообщает о собственных аппаратных исследованиях и библиотеке +Drive. Дочерние страницы `docs` через web-reader не загрузились; детали из их исходников не использовались.
