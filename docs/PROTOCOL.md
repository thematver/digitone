# Протокол и происхождение реализации

Реализация на Swift написана отдельно по документированным форматам. Исходники GPL-проектов не переносились; внешних библиотек протокола нет. В нативном Mac-приложении проверены идентификация Digitone II OS 1.10D build 0049 и чтение A01 с проверкой checksum и декодированием. Остальные возможности протокола подтверждаются отдельно; [журнал проверок](VALIDATION.md) фиксирует их границы.

## Источники

- [Официальное руководство Elektron OS 1.10C](https://www.elektron.se/wp-content/uploads/2025/07/Digitone-2-User-Manual_ENG_OS1.10C_250708.pdf), разделы MIDI CONFIG, SYSEX DUMP, USB CONFIG и приложение C: настройки связи и таблицы CC/NRPN. Руководство не описывает весь внутренний бинарный протокол; версия целевого прибора — 1.10D.
- [Описание SysEx в digi-roll](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/elektron-sysex-protocol.md): заголовки, упаковка байтов, идентификация и контроль передачи.
- [Исследование паттернов Digitone II](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/dn2-pattern-format.md): размеры и позиции полей для OS 1.10D build 0049. Источник отмечает собственные аппаратные проверки и предположения; это результаты авторов digi-roll.

Источники прочитаны 3 октября 2026 года. Ссылки на ветку `main` могут изменяться; перед расширением поддержки сверяйте документ и конкретные аппаратные фикстуры.

## MIDI и параметры

Потоковый парсер сохраняет состояние между пакетами, выделяет SysEx и канальные сообщения, обрабатывает running status и отдельно учитывает realtime-байты. CC передаёт значение 0–127. NRPN-селектор собирается из CC 99/98, данные — из CC 6/38; состояние хранится по каналу.

Каналы интерфейса 1–16 кодируются в MIDI как 0–15. Редактор использует грубую MIDI-шкалу и не обещает точное отображение дробных величин. Назначение каналов треков задаётся на приборе; приложение не должно молча считать номер трека номером его MIDI-канала.

На реальном приборе `OUTPUT CH = AUTO CH`: при активном треке 1 CC пришли на Auto Channel 10. Подтверждены Frequency (`CC 16`, наблюдались 13 и 25), FLTR · F (`CC 17`, 0) и Filter Attack (`CC 20`, 5), с отметками «Получено» в UI. Назначение FLTR · F зависит от аппаратной FLTR machine; декодер не угадывает тип фильтра. Эта проверка относится только к приёму трёх грубых CC-значений.

## SysEx

Производитель: `F0 00 20 3C`. Конец сообщения: `F7`. В восьмибайтовой группе первый байт содержит старшие биты следующих семи байтов; биты идут от 6 к 0. Неполная последняя группа допускается.

API-заголовок: `F0 00 20 3C 10 00`. Распакованное тело: `messageID:u16be`, `responseID:u16be`, `opcode:u8`, аргументы. Ответ сопоставляется по ID и `opcode | 0x80`. Используются запросы `01` (прибор) и `02` (OS/build); product ID Digitone II — `43`. Строки завершены нулём и декодируются как Windows-1252.

Для дампов семейство Digitone II — `15`; запрос паттерна с kit — `60`, ответ — `50`. Затем идут версия `01 01`, индекс слота, упакованные данные, checksum и count. Обе величины — по два семибитных байта: сумма упакованного payload modulo 16384; его длина плюс 5 modulo 16384. Запрос имеет пустой payload и хвост `00 00 00 05 F7`. Проверки структуры и checksum выполняются до чтения полей. Эти детали основаны на [описании SysEx](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/elektron-sysex-protocol.md).

## Читаемый паттерн

Декодер принимает семейство `15`, тип `50`, версию `01 01` и payload длиной 99840 байтов. Числовые поля ниже используют big-endian.

| Смещение | Читаемое поле |
|---:|---|
| 0 | Версия pattern struct: 3 |
| 4 | 16 треков по 1187 байтов |
| 18996 | 8192 записей по 6 байтов: track, step, note, velocity, length, microtiming |
| 88788 | Имя паттерна, до 16 байтов |
| 88804 | Темп: u32 / 120 |
| 88812 | Swing: байт + 50 |
| 89088 | Kit magic `BEEFBACE`, затем версия 3 |
| kit + 60 | 16 структур по 359 байтов; имя звука в +12 |

Трек хранит 128 двухбайтовых step words; бит `0001` включает триггер. В defaults +1152 лежат note/velocity/length и длина трека в +12. У свободной записи track равен `FF`; один шаг может иметь несколько записей нот. `FF` в значении заменяется соответствующим track default; microtiming — знаковый байт. Эти поля описаны в [исследовании паттернов](https://raw.githubusercontent.com/zooloo303/digi-roll/main/docs/dn2-pattern-format.md).

Исходный `.syx` сохраняется полностью. Неизвестные поля не реконструируются. Декодер не выдаёт kit за полноценный прочитанный пресет; извлечённое имя не означает, что разобраны все параметры звука.

Экспорт A01 из реального прибора проверен повторным чтением файла через CLI `inspect` и импортом в UI при отключённом MIDI: checksum, структура и вывод значений прошли. Ссылка на локальный дамп и его SHA-256 приведены в [журнале проверок](VALIDATION.md).

Локальная библиотека schema 1 также проверена: снимок трёх параметров сохранился в Application Support, пережил перезапуск и загрузился как черновик без подключения к MIDI. Это проверка сохранности и восстановления данных приложения; восстановление этих параметров на приборе ещё не подтверждено.

## Сессия и границы

Один запрос идентификации ожидает ответ 5 секунд; запрос паттерна — 15 секунд. Параллельные чтения паттернов запрещены. Отключение отменяет ожидания и сбрасывает NRPN-состояние. Отложенный note-off не должен направляться вновь выбранному MIDI-порту.

Публичная сессия отправляет идентификационные запросы, пустые запросы чтения паттернов, CC/NRPN и тестовые ноты. Аппаратно проверены идентификационные запросы, чтение A01 и приём трёх общих CC-параметров. Отправка CC/NRPN, приём NRPN и прослушивание пока ожидают проверки на приборе. Запись payload в паттерн, восстановление проекта, файл API +Drive и Overbridge не реализованы. Статус «соединено» означает успешный handshake, но не чтение текущего звука.

До расширения версии формата нужны реальные записи с одним контролируемым изменением, описание OS/build, сравнение с дисплеем прибора и регрессионные проверки. Тесты на искусственных данных проверяют кодирование и отказы на повреждённых сообщениях; аппаратную совместимость они не подтверждают.

В текущей аппаратной проверке A01 содержит 0 нот: успешное чтение заголовков, настроек и имени звука не подтверждает декодирование заполненных нотами паттернов. Нужна отдельная запись с нотами, аккордом, velocity, длинами и microtiming. Командный CoreMIDI-клиент ограниченной среды вернул −10833; нативное приложение на этом Mac успешно работает с MIDI-сервисом.
