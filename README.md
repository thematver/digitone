# Digitone Studio

Нативный редактор для Digitone II на macOS и iOS/iPadOS. Первый этап — связь с прибором, базовые параметры звука, локальные снимки и просмотр паттернов. Целевая прошивка для исследования: **OS 1.10D**, известный формат паттернов — **build 0049**.

## Запуск на Mac

Требования: macOS 14+, Xcode с поддержкой Swift 6. Внешних зависимостей нет.

```bash
./scripts/check.sh
./scripts/build-app.sh
```

Сборка создаёт `build/Digitone Studio.app`. Открой приложение двойным щелчком в Finder; при желании перенеси его в «Программы». Это локальная сборка с ad hoc подписью. Для запуска на своём Mac аккаунт разработчика не нужен.

Для разработки открой `DigitoneStudio.xcodeproj`, выбери схему **Digitone Studio macOS** и устройство **My Mac**. Xcode использует библиотеки из Swift Package в этой же папке.

## iPhone и iPad

Открой тот же проект, выбери схему **Digitone Studio iOS**. Минимальная версия — iOS/iPadOS 17. Для установки на свой телефон или планшет выбери личную команду в **Signing & Capabilities**; заранее выбранной команды в проекте нет. Для USB-подключения нужен подходящий кабель или адаптер. Проверка связи на мобильном устройстве ещё предстоит.

Для проверки компиляции без запуска симулятора:

```bash
./scripts/check-ios.sh
```

Скрипт компилирует и связывает ядро, CoreMIDI, UI и общую точку входа для arm64/iOS 17 с установленным SDK. Результат в `.build/ios-check` — проверка кода, а не подписанное приложение для установки. Физическая установка, USB-обмен и поведение на iPhone/iPad ещё требуют проверки.

Прямая компиляция и связывание для iOS уже прошли; установка на мобильное устройство ещё не выполнялась.

В ограниченной среде автоматизации Xcode не смог записать кеш диагностики Swift Package в домашнюю папку даже с `-packageCachePath`; поэтому полный цикл Xcode-сборки здесь не подтверждён. `check-ios.sh` проверяет исходный код напрямую и не заменяет этот цикл.

## Подключение Digitone II

На приборе:

1. **SETTINGS → SYSTEM → USB CONFIG**: `USB MIDI` или `USB AUDIO/MIDI`.
2. **SETTINGS → MIDI CONFIG → PORT CONFIG**: `INPUT FROM = USB`, `OUTPUT TO = USB`. Для больших SysEx-передач Elektron рекомендует именно USB.
3. Включи `RECEIVE NOTES` и `RECEIVE CC/NRPN`.
4. Для обратной связи от ручек: `ENCODER DEST = INT + EXT`, `PARAM OUTPUT = CC` или `NRPN`.
5. В **MIDI CONFIG → CHANNELS** проверь канал нужного трека. `OUTPUT CH` должен соответствовать выбранному способу адресации — канал трека или Auto Channel.

Настройки описаны в [руководстве Elektron, разделы 13.4 и 13.6](https://www.elektron.se/wp-content/uploads/2025/07/Digitone-2-User-Manual_ENG_OS1.10C_250708.pdf).

В приложении выбери MIDI-вход и MIDI-выход Digitone II, подключись и дождись имени устройства, версии OS и номера сборки. Канал в редакторе должен совпадать с каналом на приборе. Движок выбирается на самом Digitone; выбор в редакторе задаёт соответствующие подписи, но не меняет машину на приборе. Звук тестовой ноты идёт из Digitone; приложение пока не воспроизводит и не записывает USB-аудио.

Если `OUTPUT CH = AUTO CH`, повороты ручек приходят на **Auto Channel**, независимо от номера активного трека. На проверенном приборе это **канал 10**, даже когда выбран трек 1. Приложение показывает канал последнего входящего параметра и предлагает кнопку **«Выбрать канал …»**, если канал редактора отличается.

При подключении движение ползунка сразу отправляет параметр в Digitone. Загруженный снимок или вариант A/B сначала открывается как локальный черновик; для его отправки используй **«Применить параметры»**. После смены звука или паттерна на приборе очищай известные значения: поступающие события MIDI не заменяют чтение всего состояния.

## Что есть сейчас

- Общие библиотеки для macOS и iOS: CoreMIDI, потоковый разбор MIDI/SysEx, идентификация прибора и версии OS.
- Базовый редактор общих параметров с приёмом CC/NRPN от прибора.
- Локальные снимки параметров и явная отправка подготовленных значений.
- Чтение слота паттерна, просмотр нот и сохранение исходного `.syx`.
- Диагностическая утилита `digitone-tool`.

## Проверено 3 октября 2026 года

Release-приложение для Mac собрано, подписано локальной ad hoc подписью и запущено. В обычном нативном приложении CoreMIDI работает: прибор определён как **Digitone II, OS 1.10D, build 0049**. Прочитан реальный **A01**: **120 BPM**, swing **50%**, **0 нот**; имя звука трека 1 — **KICK_SHARP**, длина трека — **16 шагов**. Полученная передача прошла проверку контрольной суммы и структурный декодер. Показания ещё не сверялись с физическим дисплеем Digitone; чтение заполненного нотами паттерна остаётся отдельной проверкой.

Реальный `.syx` экспортирован из приложения в `captures/hardware/DN2-1.10D-0049-A01.syx`; offline-команда `inspect` успешно прочитала этот файл с теми же значениями. Прошли **28 автоматических тестов** и прямая компиляция/связывание iOS. Экраны подключения и прочитанного паттерна визуально проверены. Подробные границы этих результатов — в [VALIDATION](docs/VALIDATION.md).

Приём **CC от ручек** также подтверждён на MIDI-канале 10: получены три общих параметра, Frequency обновлялась в реальном времени. Это проверка грубых значений 0–127; отправка параметров в прибор и NRPN ещё не подтверждены.

Локальный снимок **«FILTER · первый снимок»** сохранён с тремя параметрами, пережил закрытие и перезапуск приложения и открылся как черновик при отключённом MIDI. Реальный `.syx` A01 также повторно открыт через интерфейс без подключения к прибору. Последняя Mac-сборка с диагностикой входящего канала и её подпись, а также iOS-проверка компиляции/связывания прошли.

## Ограничения первого этапа

Значения редактора представлены в грубой MIDI-шкале **0–127**. Это ещё не отображаемые прибором значения всех параметров; тонкая часть NRPN не воспроизводится полностью. MIDI-отправка сама по себе не подтверждает совпадение значения на приборе.

**Снимок приложения содержит только известные ему параметры.** Это не полноценный аппаратный пресет: все параметры движка, машин, модуляции и исходное несохранённое состояние ещё не считываются. Загрузка снимка не означает восстановление всего звука.

Паттерны доступны **только для чтения**. Запись обратно, piano roll с редактированием, MIDI Clock, транспорт, синхронизация проектов, Overbridge, облачная библиотека и сэмплер пока не реализованы. Структурный декодер ограничен изученным форматом; неизвестные версии не интерпретируются автоматически.

Командная проверка из ограниченной среды автоматизации получила от CoreMIDI **−10833**: MIDI-сервис недоступен тому процессу. Это ограничение не воспроизвелось при обычном запуске приложения: идентификация, чтение A01 и приём трёх общих CC-параметров успешно выполнены. Отправка CC/NRPN, приём NRPN, тестовая нота, восстановление параметров и физическое iOS-устройство пока не проверены.

## Первая проверка на приборе

Работай с отдельным тестовым проектом: редактор меняет текущие параметры трека.

1. **Связь.** Уже подтверждена в Mac-приложении: `Digitone II`, `1.10D`, build `0049`.
2. **Чтение.** A01 уже получен и экспортирован, файл проверен через `inspect` и повторно открыт в UI без подключения. Сравнить значения с физическим дисплеем прибора и прочитать заполненный паттерн.
3. **Обратная связь.** CC-приём трёх общих параметров уже подтверждён на Auto Channel 10. Отдельно проверить NRPN и остальные параметры с верным MIDI-каналом.
4. **Редактирование.** Изменить один параметр ползунком в подключённом приложении. Проверить изменение на дисплее Digitone.
5. **Прослушивание.** Отправить тестовую ноту; убедиться, что играет нужный трек и нота прекращается.
6. **Библиотека.** Сохранение снимка, сохранность после перезапуска и загрузка черновика уже проверены. Применить его на приборе и проверить восстановление этих трёх значений; остальные параметры звука в этот тест не входят.
7. **Переподключение.** Отсоединить USB во время ожидания ответа. Приложение должно завершить ожидание с понятной ошибкой; после подключения заново определить прибор.

Список сочетает подтверждённое подключение и чтение с оставшимися аппаратными проверками; текущие результаты зафиксированы в [VALIDATION](docs/VALIDATION.md).

## Диагностика

После `./scripts/check.sh` утилита находится в `build/bin/digitone-tool`:

```bash
build/bin/digitone-tool list
build/bin/digitone-tool identify
build/bin/digitone-tool capture 0 captures-A01.syx
build/bin/digitone-tool inspect captures/hardware/DN2-1.10D-0049-A01.syx
```

`capture` принимает индекс **0–127**: `0 = A01`, `15 = A16`, `16 = B01`, `127 = H16`. Команда читает слот текущего проекта; CLI автоматически выбирает первые MIDI-порты, в имени которых есть `Digitone`. Исходный файл сохраняется без редактирования содержимого. `inspect` читает сохранённый дамп без обращения к MIDI-сервису; реальный файл A01 уже проверен этой командой.

## Структура

| Компонент | Назначение |
|---|---|
| `Sources/DigitoneCore` | Протокол, MIDI-парсер, параметры, снимки и формат паттернов |
| `Sources/DigitoneMIDI` | CoreMIDI и запросы к прибору |
| `Sources/DigitoneUI` | Общий SwiftUI-интерфейс |
| `Sources/DigitoneStudio` | Точка входа приложения для сборки Swift Package |
| `App` | Общая точка входа приложений Xcode |
| `Sources/DigitoneTool` | Утилита диагностики |
| `Tests` | Проверки протокола на искусственных данных |

`scripts/check.sh` запускает тесты, собирает оба исполняемых продукта и помещает диагностическую утилиту в `build/bin`. `build-app.sh` создаёт release-приложение без отладочных символов. Кеши остаются в `.build`; скрипты не запускают GUI и не отправляют MIDI. Тесты проверяют обработку данных, но не заменяют проверку на Digitone.

Порядок дальнейшей работы — в [ROADMAP](docs/ROADMAP.md); источники и формат данных — в [PROTOCOL](docs/PROTOCOL.md); фактические проверки — в [VALIDATION](docs/VALIDATION.md).
