# Digitone Studio

Нативная студия для Digitone II на macOS и iOS/iPadOS. Редактор звуков, пошаговый секвенсор и библиотека объединены вокруг работы с прибором; локальный MCP-сервер открывает эти музыкальные операции агентам. Целевой прибор — **Digitone II OS 1.10D, build 0049**.

## Рабочие сценарии

Студия открывается в **Паттерне**. Три раздела всегда под рукой:

| Раздел | Что можно делать |
|---|---|
| **Паттерн** | Собрать бит в пошаговой сетке: 16/32/64 шага, страницы по 16, роли Kick/Snare/Hat/Bass и стартовые House/Breakbeat/Minimal. Редактировать ноту, velocity и длину, mute дорожки, явные MIDI-каналы, undo/redo. Переключиться в piano roll для мелодий, аккордов и живой записи |
| **Звук** | Выбрать трек, его машину и канал; редактировать параметры с именами, числом, слайдером и точным вводом. Начать с частичного шаблона тембра, подготовить локальный черновик, применить его к прибору; отдельно доступны общие FX |
| **Библиотека** | Найти сохранённый звук по имени/тегам/движку, открыть его в редакторе, менять метаданные, импортировать/экспортировать JSON и хранить исходные SysEx-архивы |

Создавать паттерны и черновики звуков можно без Digitone. Подключение требуется для прослушивания на приборе. Паттерн автоматически сохраняется после правок; файлы с ошибками не перезаписываются. Кнопки **Подключить Digitone**, **Запись** и **Агенты** доступны из всех разделов. На Mac: ⌘1/2/3 переключают разделы, ⌘⇧K открывает подключение, ⌘⇧R — запись.

**Лента и сэмплер убраны из основной навигации.** Запись стала утилитой: USB-аудиовход → WAV-дубли → прослушивание и экспорт. Резка чужого аудио на пэды больше не представляется как работа с Digitone.

## MCP для агентов

В приложение включён отдельный сервер **digitone-mcp**, транспорт **stdio**, 22 инструмента. Агент может обнаружить MIDI-устройство, получить каталог параметров, создать/править черновик звука, отправить его в Digitone, собрать и редактировать бит или мелодию, проиграть/остановить партию, сохранить проект и экспортировать MIDI.

Открой **Агенты** в приложении и скопируй путь/конфигурацию сервера. Сервер находится рядом с основным исполняемым файлом в `Digitone Studio.app/Contents/MacOS/digitone-mcp`. Для разработки `scripts/check.sh` помещает его в `build/bin/digitone-mcp`.

Агент и UI обмениваются проектами **.digitone.json**: меню «•••» → **Открыть проект агента** / **Экспорт проекта**. При открытии ноты становятся редактируемым паттерном, звуки добавляются в библиотеку. Открытие проекта ничего не отправляет в прибор. Это обмен файлами между самостоятельными сессиями; агент не управляет открытым окном и его транспортом.

Партия проигрывается с компьютера через MIDI; запись во внутреннюю память аппаратного секвенсора пока не реализована. Применение звука меняет только заданные параметры текущего трека, не сохраняет полный аппаратный пресет. Машина SYN/FLTR выбирается на самом Digitone. В экспортируемом проекте значения звука имеют грубую MIDI-шкалу 0…127; точные NRPN-значения редактора округляются до старшей части.

Настройка, полный список инструментов и примеры: [docs/MCP.md](docs/MCP.md).

## Запуск на Mac

Требования: macOS 14+, Xcode с поддержкой Swift 6. Внешних зависимостей нет.

```bash
./scripts/check.sh
./scripts/build-app.sh
```

Сборка создаёт `build/Digitone Studio.app` с локальной ad hoc подписью. Открой её в Finder; для запуска на своём Mac аккаунт разработчика не нужен. Для разработки открой `DigitoneStudio.xcodeproj`, схему **Digitone Studio macOS**, устройство **My Mac**.

## iPhone и iPad

В том же проекте выбери **Digitone Studio iOS**. Минимальная версия — iOS/iPadOS 17. Для установки выбери свою команду в **Signing & Capabilities**. Для USB MIDI нужен подходящий кабель или адаптер.

```bash
./scripts/check-ios.sh
```

Прямая компиляция и связывание всех модулей и общей точки входа для arm64/iOS 17 прошли. Артефакты в `.build/ios-check` служат проверкой кода; это не подписанное приложение для установки. Статус полной Xcode-сборки и физического iPhone/iPad — в [VALIDATION](docs/VALIDATION.md).

## Подключение Digitone II

На приборе:

1. **SETTINGS → SYSTEM → USB CONFIG**: `USB MIDI` или `USB AUDIO/MIDI`.
2. **MIDI CONFIG → PORT CONFIG**: `INPUT FROM = USB`, `OUTPUT TO = USB`; включи `RECEIVE NOTES` и `RECEIVE CC/NRPN`.
3. Для обратной связи от ручек: `ENCODER DEST = INT + EXT`, `PARAM OUTPUT = CC` или `NRPN`.
4. Проверь каналы треков, `AUTO CHANNEL`, `FX CONTROL CH` и `OUTPUT CH`. На ранее проверенном приборе `OUTPUT CH = AUTO CH` передавал общие параметры на **канале 10**, даже при активном треке 1. Укажи тот же режим и каналы в панели подключения приложения.

Настройки описаны в [руководстве Elektron, разделы 13.4 и 13.6](https://www.elektron.se/wp-content/uploads/2025/07/Digitone-2-User-Manual_ENG_OS1.10C_250708.pdf).

В приложении выбери MIDI-вход/выход, подключись и дождись имени, OS и build. Каналы треков в пульте и дорожек piano roll должны совпадать с прибором. Выбор машины в приложении меняет каталог и визуализацию; машину на Digitone нужно выбрать отдельно. При подключении движение ручки сразу отправляется в прибор. Снимок и A/B загружаются как локальные черновики и отправляются кнопкой **«Применить черновик»**. После смены паттерна прежние полученные/отправленные значения становятся неизвестными; локальные черновики сохраняются.

## Слушать Digitone через Mac

Мониторинг включён по умолчанию: USB-аудиовход Digitone → динамики или наушники Mac. Значок наушников в верхней панели открывает маршруты, громкость, уровни L/R и оценку задержки. Автоматический выбор выхода исключает Digitone; явный маршрут обратно в тот же USB-прибор блокируется, чтобы избежать петли. Встроенный микрофон автоматически не включается. Выбор входа/выхода и состояние мониторинга сохраняются.

На приборе нужен `USB AUDIO/MIDI` и подходящий источник `USB OUT`. При первом запуске мониторинга запрашивается системное разрешение на аудиоввод. Дубли записываются через кнопку «Запись»; воспроизведение работает через тот же выход и сохраняет мониторинг.

В «Паттерне» переключись в редактор «Ноты» и играй клавишами **A W S E D F T G Y H U J K**; **Z/X** меняют октаву. Запись принимает экранную клавиатуру, Musical Typing и входящие MIDI-ноты; доступны живой и шаговый режимы. Колёсико прокручивает сетку, масштаб задаётся в панели, щипок меняет масштаб. Ноты можно выделять рамкой, переносить группой, растягивать и менять velocity.

## Подтверждённые результаты

В предыдущей аппаратной проверке **3 октября 2026** обычное Mac-приложение определило **Digitone II, OS 1.10D, build 0049** и прочитало **A01**: 120 BPM, swing 50%, 0 декодированных нот, T1 **KICK_SHARP**, длина 16 шагов. SysEx прошёл checksum и структурный декодер, был экспортирован, проверен через `inspect` и повторно открыт в UI без MIDI. С физическим дисплеем данные A01 ещё не сверялись.

Подтверждён приём трёх общих CC-параметров на канале 10. Пользователь также подтвердил один сценарий отправки и возврата **Frequency: 33 → 34 → 33**, включая возврат Frequency при применении локального снимка. Это не проверка остальных параметров или восстановления всего звука. Снимок из трёх значений пережил закрытие и повторный запуск приложения.

Карта пульта охватывает все **167 строк приложения C** руководства OS 1.12, включая EUCLID и INPUT R. Полная совместимость карты и кодирование списков на OS 1.10D ещё не проверены. Автоматические результаты, 80 статических состояний интерфейса и границы аппаратной проверки — в [VALIDATION](docs/VALIDATION.md).

## Границы текущей версии

- **Снимки содержат только известные параметры** в грубой шкале 0–127. Полный текущий звук, несохранённые изменения, точные диапазоны и тонкая часть NRPN ещё не восстанавливаются.
- Схемы страниц/машин и огибающих в «Звуке» иллюстративные: это не измеренная осциллограмма Digitone и не точная программная модель. MIDI-шкала не калибрована в физических единицах. В «Ленте» отображаются данные открытого аудио или входа.
- **SysEx-архивы сохраняются байт в байт** после проверки целостности; повторный импорт пропускает идентичные файлы. Архив может содержать несколько дампов. Это ещё не декодированная библиотека всех пресетов, доступ к +Drive или отправка банка обратно в конкретный слот.
- **Аппаратные паттерны доступны для чтения.** Их ноты можно открыть как локальную партию; редактирование не записывается в паттерн Digitone. Conditions, probability и parameter locks этим переносом не воспроизводятся.
- Импорт MIDI поддерживает SMF 0/1 с PPQ; сохраняет ноты, имена дорожек, первый темп и первый размер. Карта темпа, CC, program changes, SysEx и SMPTE не переносятся. Экспорт — SMF 1, 96 PPQ. Сетка piano roll прокручивается и масштабируется; разметка тактов учитывает размер партии.
- Планировщик использует временные метки CoreMIDI и завершает ноты при остановке. MIDI Clock/транспорт реализованы на уровне API; кнопка воспроизведения UI запускает ноты без Clock. Полный синк проектов, Overbridge и облачная библиотека ещё не реализованы.
- Аудиозапись, маршрутизация, задержка, отключение устройств, фон и сэмплер требуют проверки с живым оборудованием и на iOS. Наличие аудиодвижка не подтверждает USB-маршрут Digitone.

При закрытии окна/выходе на Mac и уходе iOS-приложения в фон предусмотрены завершение записи с сохранением дубля, остановка сэмплера и отключение MIDI с завершением нот. После фона нужно подключиться снова. Состояние iOS `inactive`, системное разрешение и открытие sheet не вызывают эту остановку; поведение на физическом устройстве ещё предстоит проверить.

## Проверка экранов

```bash
./scripts/render-snapshots.sh
```

Скрипт создаёт **76 PNG** в `build/snapshots`: три раздела и дополнительные состояния piano roll, пульта и мониторинга × Mac/phone × светлая/тёмная тема. Можно указать `--output build/snapshots-round2` и фильтр имени. Используются искусственные партии, снимки и аудио; подключения MIDI/аудиоввода нет. Нативные поля/меню/ползунки заменяются нарисованными представлениями. Рендер проверяет композицию, но не взаимодействие с настоящими системными контролами.

## Диагностика

После `check.sh` утилита находится в `build/bin/digitone-tool`:

```bash
build/bin/digitone-tool list
build/bin/digitone-tool audio-list
build/bin/digitone-tool audio-monitor 5
build/bin/digitone-tool identify
build/bin/digitone-tool capture 0 captures-A01.syx
build/bin/digitone-tool inspect captures/hardware/DN2-1.10D-0049-A01.syx
```

`capture` читает слот текущего проекта: `0 = A01`, `15 = A16`, `16 = B01`, `127 = H16`. CLI выбирает первые порты с `Digitone` в имени. `inspect` работает с файлом без MIDI; реальный A01 уже проверен этой командой. Прямой CLI capture с прибора ещё не подтверждён: ранее ограниченный командный процесс получил CoreMIDI **−10833**, а обычное Mac-приложение работало успешно.

## Структура

| Компонент | Назначение |
|---|---|
| `DigitoneCore` | Протокол, MIDI/SysEx-парсер, снимки/архивы, паттерны, партии и `.mid` |
| `DigitoneMIDI` | CoreMIDI, запросы к прибору, часы и воспроизведение по временным меткам |
| `DigitoneDSP` | Анализ спектра/транзиентов, работа с сэмплами и источник сэмплерного звука |
| `DigitoneAudio` | AUHAL/AVAudioEngine, независимый USB-вход/выход, мониторинг, запись, файлы, воспроизведение и DSP |
| `DigitoneKit` | Подготовленные общие сервисы связи и состояния |
| `DigitoneAgent`, `digitone-mcp` | Проверяемые проекты, MIDI-операции агентов и протокол MCP stdio |
| `DigitoneDesign`, `DigitoneUI` | Тема, визуальные компоненты, три раздела и состояние интерфейса |
| `DigitoneSnapshots` | Статический рендер экранов |
| `App`, `DigitoneStudio`, `DigitoneTool` | Точки входа Xcode/Swift Package и диагностика |

`check.sh` запускает тесты и собирает оба исполняемых продукта. Скрипты сборки не запускают GUI и не отправляют MIDI. Дальнейшая работа — в [ROADMAP](docs/ROADMAP.md), изученный протокол — в [PROTOCOL](docs/PROTOCOL.md).
